# aTrust Wiki 平台适配指南

## agent-browser 标准命令

始终保持同一会话名：

```powershell
$s = 'atrust-kb'
agent-browser --session $s get url
agent-browser --session $s snapshot -i --json
```

进入精确页面而不是知识库首页后猜测路径：

```powershell
agent-browser --session $s open '<用户提供的完整 URL>'
agent-browser --session $s wait --load domcontentloaded
agent-browser --session $s snapshot -i --json
```

搜索或点击会使引用失效。每次页面变化都重新 snapshot，再使用新的 `@eN`。

下载单个附件：

```powershell
agent-browser --session $s download '@eN' 'D:\absolute\downloads\file.ext'
```

不得把示例引用 `@eN` 写死到自动化脚本中。

## 已确认入口特征

- 业务域名：`kb.atrust.sangfor.com`
- 常见入口：`plugin.php?id=wiki:index&space_id=<SPACE_ID>#/option/<OPTION_ID>`
- `space_id` 表示知识空间；hash 路由中的标识可能对应栏目、目录或页面上下文，不能假定为永久文档 ID。
- 未登录请求可能跳转到深信服统一接入/SSO 门户，例如 `sdpc.sangfor.com`。此跳转说明需要用户授权的登录会话，不代表原文档不存在。

以上仅作为定位线索。以当前页面可见内容、最终 URL 和站内导航为准。

## 页面结构发现

每次首次进入一个新空间或页面布局变化时，先获取一次可见 DOM 快照，识别以下区域：

1. 顶部或侧栏的搜索框、搜索按钮、范围选择器
2. 空间名称、目录树、面包屑
3. 结果列表及标题链接、摘要、时间、类型
4. 文档标题、正文容器、更新时间、版本标签
5. 附件区域、文件链接、导出/下载按钮、内嵌预览器

从最新快照中构造定位器。优先级：稳定 `data-*` 属性、精确 `href`、语义角色与可访问名称、作用域内文本、CSS。动作前确认目标唯一；动作后只做下一步需要的最小状态检查。

## 搜索回退策略

按以下顺序执行，命中后停止扩大：

1. 精确标题或完整短语
2. 标题去除括号中的版本、日期、标点
3. 产品名 + 模块名 + 核心动作
4. 两到三个区分度最高的关键词
5. 指定空间内目录浏览

不要组合大量猜测 URL。站内搜索不可用时，从当前空间目录树导航；只有用户提供明确页面或附件直链时才直接访问该 URL。

## 候选排序

候选较多时，按以下信号综合排序：

1. 标题完全一致
2. `space_id` 或空间名称一致
3. 产品与版本一致
4. 目录上下文一致
5. 更新时间满足用户条件
6. 摘要包含全部核心关键词

不能仅因结果排第一就视为命中。打开详情核对至少两个独立信号。

## 附件发现

附件可能表现为：

- 独立附件列表中的文件名
- 正文内文件链接
- “下载”“导出 Word/PDF”等按钮
- PDF、Office 或图片预览器的工具栏按钮
- 点击后产生下载事件的无扩展名链接

先读取可见文件名、扩展名和大小。若下载 URL 是短期签名地址，只在当前登录会话中通过页面触发，不复制为长期链接。

页面中出现“文档说明 + 文档附件 + 更新时间”的表格时，把每一行视为一个候选文档单元。先按“文档说明”判断主题，再以“文档附件”的真实文件名作为下载目标。用户询问内容时，至少下载并读取一个直接相关附件；问题跨多个主题时读取覆盖各主题的最小附件集合。

## 下载验证

每个文件至少检查：

- 最终文件存在且大小大于 0
- 文件头与扩展名基本匹配：PDF `%PDF-`、ZIP/Office `PK`、图片标准魔数
- 响应不是 HTML 登录页或错误页
- 文件名可追溯到来源文档

若浏览器下载 API返回临时路径，将文件复制到目标目录后再次验证。若浏览器要求下载权限，在用户已明确要求下载的前提下按浏览器能力说明处理；其他权限请求仍需确认。

验证通过后立即进入附件解析，不得把“发现附件”或“下载成功”等同于“已理解内容”。

## 批量策略

- 默认串行或小批次处理，避免触发限流和混淆下载归属。
- 使用清单记录 `文档标题 -> 详情 URL -> 附件名 -> 本地路径 -> 状态`。
- 同名文件采用 `<文档标题>__<原文件名>`；清理文件名中的 Windows 非法字符。
- 单项失败不影响后续可独立处理的项目，但认证失效、空间权限不足或站点整体异常时停止批量任务。

## 常见失败与处理

| 现象 | 判断 | 处理 |
|---|---|---|
| 跳转 SSO/登录页 | 无有效登录态 | 切换到已有授权会话；否则请用户登录 |
| 403/无权限 | 账号无空间或文档权限 | 报告目标和权限状态，不绕过 |
| 搜索无结果 | 范围或关键词过窄 | 按回退策略逐步放宽并记录条件 |
| 页面有标题但正文空白 | 动态内容未加载、权限或 iframe | 等待明确加载信号，检查可见 iframe/错误提示 |
| 点击下载得到 HTML | 登录失效或跳转错误 | 删除无效临时文件，重新认证后重试一次 |
| 多个同名附件 | 来自不同文档/版本 | 用文档标题、版本或序号重命名 |
| 页面布局变化 | 旧定位器失效 | 重新获取 DOM 快照并按结构发现流程定位 |

## 最小审计记录

对每次任务保留在回复中的最小可追溯信息：查询条件、检索范围、命中文档标题、详情 URL、下载文件绝对路径、失败原因。不要记录 Cookie、令牌或账号敏感信息。
