# aTrust 知识库文档查询与下载

把站点视为需要 aTrust 网络环境和登录态的动态 Wiki。首选 `agent-browser` 启动独立、可见、持久化的 Chrome 会话。不要读取或导出 Cookie、令牌、密码、Local Storage 或其他认证材料。

执行前读取 [references/platform-guide.md](references/platform-guide.md)。环境初始化使用 [scripts/setup-agent-browser.ps1](scripts/setup-agent-browser.ps1)。

## 强制执行链

按顺序完成以下状态，不得仅根据列表标题或页面摘要回答需要内容理解的问题：

1. 检查或安装 `agent-browser`
2. 打开用户提供的准确入口并确认登录状态
3. 在正确空间/目录中检索并收窄候选文档
4. 核对文档标题、目录、版本、更新时间和附件列表
5. 下载与问题直接相关的附件
6. 按文件类型解析附件正文、表格、备注和内嵌材料
7. 基于附件证据综合回答并列出来源

## 解析请求

从用户输入中提取以下条件，未提供的保持为空，不要擅自缩小范围：

- 入口 URL、域名、`space_id`、hash 路由中的 option/page 标识
- 标题、关键词、短语、产品名、模块、版本、发布日期或更新时间
- 文档类型、附件格式、目录/栏目、结果数量和保存目录
- 是只返回检索结果、读取正文、下载附件，还是三者都做

用户给出精确 URL 或精确标题时直接执行。只有同名结果无法区分、下载范围会显著扩大或目标目录不明确且可能覆盖文件时，才询问一个必要问题。

## 初始化 agent-browser

1. 运行 `Get-Command agent-browser` 和 `agent-browser --version`。
2. 命令不存在时，主动运行 `scripts/setup-agent-browser.ps1`；该脚本使用 npm 全局安装并验证命令。执行安装前用一句话告知用户正在安装依赖，不必再次询问。
3. 命令存在时直接复用，不重复安装；异常时先运行 `agent-browser doctor`，仍不可用再重装。
4. 使用稳定会话名和独立配置目录。默认会话为 `atrust-kb`，配置目录为当前工作区 `.agent-browser/atrust-profile`，下载目录为 `downloads/atrust-kb`。
5. 使用 `--headed --profile <dir> --session <name>` 打开准确入口。若需要登录，保留窗口并请用户在该窗口完成登录；登录后使用相同会话继续。
6. 每次命令都显式传入同一 `--session`。页面变化后重新执行 `snapshot -i --json`，不得继续使用旧 `@eN` 引用。

示例：

```powershell
& "$PSScriptRoot/scripts/setup-agent-browser.ps1" -TargetUrl $url
agent-browser --session atrust-kb snapshot -i --json
```

不用搜索引擎、镜像站或猜测接口绕过登录。不要使用 `cookies`、`storage`、HAR 或网络拦截命令获取认证材料。

## 查询文档

1. 打开用户给出的入口；没有入口时使用 `https://kb.atrust.sangfor.com/`。
2. 记录当前空间、目录路径和页面 URL。URL 中存在 `space_id` 时将其作为默认检索范围，不硬编码示例空间。
3. 获取 `agent-browser --session atrust-kb snapshot -i --json`，优先使用站内全局搜索；若用户指定空间或栏目，应用对应范围筛选。没有全局搜索时使用目录树、当前空间搜索或页面内搜索。
4. 先按完整标题/精确短语查询；无结果时依次尝试核心关键词、去除版本/标点后的标题、产品名加模块名。每次改变条件都记录变化。
5. 对候选结果提取：标题、空间、目录路径、更新时间、摘要、详情 URL、是否包含附件。
6. 精确命中时打开详情并核对标题、产品/版本、目录上下文；多结果时按标题匹配、空间匹配、版本/时间匹配排序，不仅凭列表顺序选择。
7. 用户明确只要求“有哪些文档”时，可以仅返回候选表。用户要求“内容、方案、做法、总结、分析、回答问题”时，必须继续下载和读取附件。

## 收窄文档

1. 建立候选清单：文档说明、附件名、目录、接口人、更新时间和详情 URL。
2. 按用户问题拆成主题词，例如行业、场景、销售、交付、装备、案例、故障，再选择直接覆盖这些主题的最少文档集合。
3. 优先读取“请先阅读”、指导、方案、话术、案例集等主文档；同一主题有多个版本时优先最新且标题匹配的版本，并保留版本差异说明。
4. 打开候选详情或当前表格行，确认附件真实存在。不能仅依据左侧目录名称、列表标题或下载次数作内容结论。

## 下载文档与附件

1. 在详情页或文档表格中识别文件名链接、“附件”“下载”“导出”或预览器工具栏。
2. 下载前确定范围：用户点名的文件、当前文档全部附件、搜索结果中的全部文档，三者不要混淆。
3. 用最新 snapshot 中唯一的文件链接引用执行 `agent-browser --session atrust-kb download @eN <absolute-path>`。引用不唯一时按精确文件名定位；页面变化后重新 snapshot。
4. 保存到用户指定目录；未指定时保存到当前工作区下新建的 `downloads/atrust-kb/`，保留服务器文件名。重名时添加文档标题或递增后缀，不覆盖已有文件。
5. 每个下载后验证文件存在、大小大于 0、扩展名或 MIME 类型合理；HTML 登录页、错误页或 JSON 错误响应不得报告为成功文档。
6. 批量下载时逐项记录成功、跳过、失败及原因。不要无限重试；认证失效时停止并请求用户重新登录。
7. 若页面只提供正文而无附件，从正文容器读取。只有用户明确要求导出时才使用平台自带导出功能，不把网页另存为文件冒充原始附件。

## 解析附件

下载不是终点。完成下载验证后继续读取与问题相关的附件：

- PDF：提取文本和表格；扫描件先 OCR；按页码记录证据。
- DOC/DOCX：提取标题层级、正文、表格、页眉页脚和批注/修订线索。
- PPT/PPTX：读取每页标题、正文、图表、备注；必要时渲染页面确认视觉关系。
- XLS/XLSX：读取工作表名称、有效数据区域、公式结果、备注和关键字段。
- ZIP：先列出成员并安全解压到独立子目录，拒绝路径穿越；再按成员类型读取，不执行其中的脚本或程序。
- 图片：OCR 文字并检查图例、流程图和关键标注。

优先使用当前环境对应的 PDF、文档、演示文稿、电子表格能力。无法解析某种格式时说明限制，不根据文件名推断内容。

## 形成答案

1. 将用户问题映射到附件中的具体章节、页码、工作表或幻灯片。
2. 区分页面元数据与附件正文证据。内容结论优先引用附件，更新时间、接口人、下载次数等引用知识库页面。
3. 多份材料互相补充时说明各自角色；出现冲突时优先最新版本并显式描述差异。
4. 回答中列出实际读取的附件、本地路径、来源文档链接和证据位置。

## 输出结果

查询结果至少包含：

| 字段 | 内容 |
|---|---|
| 标题 | 文档标题 |
| 位置 | 空间与目录路径 |
| 匹配依据 | 标题、关键词、版本或时间 |
| 更新时间 | 页面可见时填写，否则写“未显示” |
| 链接 | 可追溯详情 URL |
| 附件 | 附件名或“未发现” |
| 状态 | 已定位、已读取、已下载、失败 |

下载完成后给出绝对文件路径、文件大小和来源文档链接。失败时说明卡在登录、权限、无结果、入口缺失、下载响应异常还是页面结构变化，并保留已确认的候选信息。

## 安全边界

- 仅访问用户有权访问的知识库内容，不尝试绕过 SSO、验证码、权限或下载限制。
- 不泄露或持久化认证信息，不把内部文档上传到第三方服务。
- 不点击编辑、发布、删除、评论、共享、权限设置等写操作。
- 下载可能含敏感信息的资料时，仅保存到用户指定或当前工作区目录，不转发到其他位置。
